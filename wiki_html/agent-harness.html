The agent harness

The non-model infrastructure that turns an LLM into a tool-using, stateful, recoverable, and verifiable agent.

01

Harness vs Model

The model produces tokens. The harness decides what context the model sees, what tools it can call, how tool results return, when state is compacted, how errors are recovered, and how completion is verified.

LayerScope
Prompt engineeringInstructions the model receives
Context engineeringInformation loaded, withheld, summarized, or retrieved
Harness engineeringTools, loop control, state, memory, guardrails, recovery, and verification
The harness is the infrastructure around the model: tools, memory, orchestration, state, and safety.
02

Production Components

ComponentRole
Orchestration loopRuns thought/action/observation cycles
ToolsFiles, shell, search, browser, APIs, MCP, subagents
MemoryPersists useful context across sessions
Context managementControls compaction, masking, retrieval, and delegation
Error handlingTurns failures into recoverable observations when possible
GuardrailsSeparates attempted actions from permitted actions
VerificationUses tests, linters, screenshots, judges, and checklists

Research such as ReAct and Lost in the Middle explains why loop design and context placement matter.

03

Loop in Motion

assemble prompt
-> call model
-> classify output
-> validate tool calls
-> execute tools
-> package observations
-> update state/context
-> verify or continue

The loop can be simple. The hard part is everything it coordinates: permissions, schemas, compaction, retries, concurrent reads, serial writes, and termination rules.

04

Dynamic Workflows

Dynamic workflows are task-specific harnesses generated for migrations, deep research, fact checking, sorting, incident triage, evals, and adversarial review.

PatternUse
Classify and actRoute items to specialized paths
Fan out and synthesizeSplit independent subtasks, then merge results
Adversarial verificationReview output against a rubric
TournamentCompare competing attempts
Loop until doneContinue until a measurable stop condition
Dynamic workflows coordinate subagents and isolated work contexts around a task-specific harness.
05

Design Decisions

DecisionTradeoff
Single-agent vs multi-agentContext preservation vs coordination overhead
ReAct vs plan-and-executeAdaptability vs repeated reasoning cost
Thin vs thick harnessModel capability vs deterministic control
Permissive vs restrictive toolsSpeed vs safety
Tests vs LLM judgesDeterministic truth vs semantic review

Default to one agent, the smallest useful tool set, and a verifier. Add subagents or workflows only where the simpler loop breaks.
