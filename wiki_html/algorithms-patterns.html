Knowledge Vault — Algorithms

Five patterns that unlock most problems

Interview-style algorithm problems look infinite until you recognize that most of them collapse into a small number of reusable patterns. The goal is learning the invariants that tell you which tool to reach for: monotonicity for binary search, pointer movement rules, graph traversal templates, DP state transitions, and bit-level identities.

01

The Unifying Idea

The point of a pattern is not to avoid thinking. It is to narrow the search space of possible solutions.

When a problem feels hard, ask:

  • Is there a monotone predicate? → binary search
  • Is there a left/right or slow/fast invariant? → two pointers
  • Is the structure a graph or grid connectivity problem? → DFS/BFS/Union-Find
  • Is the answer built from overlapping subproblems? → dynamic programming
  • Is the state naturally encoded as bits or sets? → bit manipulation
02

Binary Search as Monotone Feasibility

The cleanest abstraction is:

Minimize k such that condition(k) is True

That framing matters because the search space is often not a sorted array. It can be an answer range, a capacity range, or a threshold.

Core Template

left, right = min_possible, max_possible
while left < right:
    mid = left + (right - left) // 2
    if condition(mid):
        right = mid
    else:
        left = mid + 1
return left

Invariants:

  • Boundaries must include all feasible answers
  • condition(mid) must be monotone
  • After the loop, left is the smallest valid answer
▶
This is why "binary search on the answer" appears in problems like shipping capacity, split-array largest sum, and any setting where "if threshold m works, anything larger also works."
03

Two-Pointer Families

One invariant lets you discard large parts of the state space in linear time. Select a family to explore:

Opposite Ends

Start at both ends and move inward when sorted order or symmetry tells you which side to discard.

  • 2-sum on sorted arrays
  • 3-sum after sorting
  • Trapping rain water
  • Palindrome / reverse-string style scans

Slow and Fast Pointers

One pointer discovers information; the other pointer uses it.

  • Linked-list cycle detection
  • Removing duplicates in-place
  • Sliding-window / caterpillar scans
  • Compression and overwrite-in-place problems

Two Inputs, Two Cursors

Maintain one pointer per array/string/list and merge or compare in linear time.

  • Merging sorted arrays
  • Subsequence checks
  • Intersection problems

Split Then Merge

Divide the structure, solve pieces, then recombine with pointer logic.

  • Merge-sort-style linked-list sorting
  • Partition / merge workflows

The real skill is defining the movement invariant clearly: what makes pointer L advance, what makes pointer R retreat, and what truth remains preserved after each move?

04

Graph Patterns

Union-Find

Reach for Union-Find when the problem is secretly about connected components, grouping / merging identities, or detecting a redundant edge. Typical question shape: "which nodes belong to the same set?"

DFS

DFS is the right default when you need to fully explore a component. Recurring sub-patterns:

  • Boundary DFS for "what is connected to the edge?"
  • Island DFS for counting disconnected regions
  • Cycle / safe-state DFS for recursive dependency graphs

BFS

BFS dominates when the problem asks for shortest path in an unweighted graph, minimum number of steps, or how long until a process spreads everywhere. Multi-source BFS is especially important: initialize the queue with every valid source at once, then expand layer by layer.

Bipartite / Coloring

If the prompt asks whether nodes can be split into two groups with no conflicts inside a group, think 2-coloring via BFS/DFS — a contradiction appears if neighbors require the same color.

05

Dynamic Programming Patterns

DP gets easier when you stop treating every problem as unique. The useful abstraction is: recognize which state-transition template this problem instantiates.

Minimum / Maximum Path to a Target

dp[i] = best(dp[previous states]) + local_cost

Typical use cases: minimum path sum, coin change, climbing-cost variants.

Count Distinct Ways

dp[i] = sum(dp[previous states])

Typical use cases: climbing stairs, unique paths, dice-roll counting.

Other High-Frequency Families

  • Merging intervals
  • DP on strings
  • Decision-making / choose-skip problems

Across all of them, the key questions are: what is the state? what smaller states transition into it? what are the base cases? do I want top-down memoized or bottom-up table?

06

Bit Manipulation

Bit manipulation turns set membership and low-level state updates into constant-time operations.

Core Operators

OperatorMeaningCommon Use
&ANDmasking, testing bits
|ORsetting bits
^XORtoggling, parity, swap tricks
~NOTinversion / masks
<<left shiftmultiply by powers of 2, build masks
>>right shiftdivide by powers of 2, extract bits

Identities Worth Memorizing

ExpressionMeaning
x & (x - 1)removes the lowest set bit
x & -xisolates the lowest set bit
x && !(x & (x - 1))tests whether x is a power of two
num & (1 << i)checks whether bit i is set

Bits let you treat an integer as a compact set: union → A | B, intersection → A & B, subtraction → A & ~B. Useful for subset DP, state compression, flags, and parity problems.
