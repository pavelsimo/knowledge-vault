Databricks bundles

Declarative Automation Bundles package Databricks jobs, pipelines, notebooks, tests, model resources, and deployment targets as source-controlled infrastructure.

ContentsWhen to UseLifecycleComparisonRelated
01

What a Bundle Contains

  • Workspace and cloud configuration
  • Source files such as notebooks and Python modules
  • Lakeflow Jobs and Spark Declarative Pipelines
  • Dashboards and Model Serving endpoints
  • MLflow Experiments and registered models
  • Unit tests, integration tests, environment targets, and deployment metadata

The key idea: Databricks resources become versioned source files instead of click-built workspace state.

02

When to Use Bundles

ScenarioWhy bundles help
Team data or ML projectsOrganize notebooks, jobs, pipelines, and tests together
MLOps stacksDeploy training, inference, registry, and serving consistently
Regulated workPreserve code and infrastructure history
TemplatesEncode defaults for permissions and CI/CD
Multi-environment deploymentPromote the same project across targets
03

Lifecycle

databricks bundle init
databricks bundle validate
databricks bundle deploy
databricks bundle run

The CLI reads YAML, resolves targets, uploads source files, creates or updates resources, and runs declared workflows.

04

Bundle vs Workspace Work

Ad hoc workspaceBundle-based
Resources created manuallyResources declared in source
Harder to review changesChanges reviewed in pull requests
Environment drift is commonTargets make differences explicit
CI/CD added laterCI/CD fits the project shape
