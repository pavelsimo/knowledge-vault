Retrieval-Augmented Generation

RAG augments LLM generation by retrieving relevant external documents at inference time, grounding the model's output in up-to-date or domain-specific knowledge without retraining. The retrieved context is injected into the prompt alongside the user's query.

01
Naive RAG
Query → Embed → Vector DB → Prompt → LLM → Output
Retrieves documents purely based on vector similarity between the query embedding and stored document embeddings. Works best for simple, fact-based queries where direct semantic matching is sufficient.
baseline
02
Multimodal RAG
Query → Embed → Vector DB (multi-modal) → Prompt → LLM
Handles multiple data types (text, images, audio) by embedding and retrieving across modalities. Ideal for cross-modal tasks: answering a text query with both text and image context. Requires modality-specific encoders (e.g., CLIP for image-text).
multimodal
03
HyDE
Query → Generate Hypothetical Doc → Embed → Vector DB → LLM
Addresses the problem where queries are not semantically similar to documents. The LLM first generates a hypothetical answer, then that answer's embedding is used to retrieve real documents. Bridges the vocabulary/style gap between short queries and long documents.
query expansion
04
Corrective RAG
Query → Embed → Analyzer → Web Search → Prompt → LLM
Validates retrieved results by comparing them against trusted sources (e.g., web search). Filters or corrects retrieved content before passing to the LLM. Useful when the knowledge base may be stale or incomplete.
freshness
05
Graph RAG
Query → Graph Generator → Graph DB + Vector DB → LLM
Converts retrieved content into a knowledge graph capturing entities and relationships. Provides structured context alongside raw text to the LLM. Enhances multi-hop reasoning over interconnected facts. Example: Microsoft GraphRAG.
multi-hop
06
Hybrid RAG
Query → Vector DB (dense) + Graph DB (structured) → LLM
Combines dense vector retrieval with graph-based retrieval in a single pipeline. Useful when the task requires both unstructured text and structured relational data. Produces richer answers by leveraging complementary retrieval signals.
hybrid
07
Adaptive RAG
Query → Analyzer → (Direct | Reasoning Chain) → Vector DB → LLM
Dynamically decides whether a query requires simple retrieval or a multi-step reasoning chain. Routes simple queries directly to retrieval (faster, cheaper). Breaks complex queries into sub-queries via reasoning chain for better coverage.
routing
08
Agentic RAG
Query → Agent (ReAct/CoT + Memory) → Tools → Output
Uses AI agents with planning, reasoning (ReAct, CoT), and memory to orchestrate retrieval from multiple sources. Best for complex workflows requiring tool use, external APIs, or combining multiple RAG techniques. The agent decides what to retrieve, when, and from where.
agents
